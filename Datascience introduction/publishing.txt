2. Explanation to add in README.md:
Why Raw Data Files Should Not Be Uploaded Directly to GitHub:
- Storage Limits: GitHub has a 100MB per-file hard limit and recommends keeping repositories under 1GB to 5GB. Git saves full history deltas, causing permanent repository bloat.
- Bandwidth and Performance: Cloning and fetching repositories with large files consumes high network bandwidth and slows down team collaboration and CI/CD pipelines.
- Privacy and PII Risks: Raw datasets may contain personally identifiable information (PII) or confidential data. Once committed, they remain in the Git commit tree permanently unless cleaned with history rewriting tools.
- Solution: Track large files with Git LFS or host raw datasets on cloud storage (AWS S3, GCP, Kaggle) and keep only clean scripts in Git.

TASK 4: SHOWCASE DATA SCIENCE WORK (NO RAW DATA)
1. Python file content (helper_functions.py):
import pandas as pd

def clean_missing_values(df):
    return df.dropna().drop_duplicates().copy()

def normalize_metric(series):
    if series.max() == series.min():
        return series
    return (series - series.min()) / (series.max() - series.min())
